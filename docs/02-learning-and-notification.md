# MVP 学习核验与微信通知设计

版本 1.0，2026年10月16日。本设计只包含管理员向指定学员发布 MP4/PDF 学习任务、微信通知真实送达闭环、过程记录、本人确认。没有课程层、考试、现场考核、定时发布和自动催办。字段及接口以[数据与接口设计](03-data-and-api.md)为准。

系统记录的是账号对应的学习行为及本人声明，可以辅助说明培训过程，不能绝对证明实际操作者、持续注意力或业务操作能力；“完成”表示满足本次任务固定规则，不表示取得行业资质或考核合格。以下参数是产品默认值，需要真机验收，不是微信提供的防作弊保证。

## 1 任务与完成条件

管理员预先建立人员，用一次性个人邀请码关联微信账号，核对通过后才能学习。任务直接关联固定版本的材料、接收人员和学习规则。发布后保留当时的文件、时长/页数和规则；更换文件或规则应建立新任务，不能改变旧任务的完成依据。

每个学员的任务按“未开始→学习中→待本人确认→已完成”展示。全部材料达标后进入待确认；本人确认接口再次检查当前人员、任务状态及服务端进度，只有条件仍满足才完成。任务取消后停止新学习和提醒，历史记录保留。截止日期仅用于提示逾期，MVP 默认允许逾期补学。

学习页面区分“已确认进度”和“待同步”。本地播到结尾、翻到末页或计时达到要求，均不能直接显示完成。管理员可以查看记录、要求补学和取消任务，没有强制改写学习进度的入口。

## 2 单人会话与通信

同一人员同时只有一个活动学习会话，跨设备、任务和材料生效。开始时通过数据库事务检查并设置人员的活动会话指针；同一人员并发请求只能成功一个。普通重复开始使用请求幂等键返回同一会话；其他设备遇到冲突，提示“其他页面正在学习”。学员明确选择“在此设备继续”才原子结束旧会话并创建新会话。

| 参数 | MVP 默认值 |
| --- | --- |
| 业务采样 | 每 1 秒一次；组件回调只更新当前状态 |
| 正常上传 | 每 5 秒批量上传，状态变化立即尝试上传 |
| 活动会话过期 | 服务端 30 秒未续期即过期 |
| 客户端暂停 | 10 秒没有成功收到确认，暂停播放与计时 |
| 连续上报边界 | 两次有效接收间隔超过 15 秒，不跨该断档计入 |
| 相邻采样边界 | 相邻采样时间差超过 3 秒，不连接有效区间 |
| 单批限制 | 最多 50 条、解压后最多 64 KB |

会话状态为 `ACTIVE / CLOSED / EXPIRED / REPLACED / REVOKED`：接管使旧会话进入 REPLACED，人员停用或任务取消使相关会话进入 REVOKED。只有当前活动会话可以续期和增加进度。过期或被接管的会话不能复活；后续日志仍可保留，但不增加进度。正常暂停仍可上传状态，前台等待期间可以保持会话，但暂停本身不增加学习时长；切后台停止计时，会话按服务器期限自然过期。

重新连接时先同步待发记录并取得服务器结果；活动会话已失效则新建会话。开始或恢复时，先立即提交当前位置的完整状态样本并取得确认，再开始累计；首批不能按请求内任意过去时间补算第一段。重新进入播放/阅读状态时建立新基线，不能把前后两个会话直接连接成一段学习时间。用户从已确认的缺失位置继续即可。

## 3 事件与幂等

事件批量上报使用业务登录凭据，服务端从会话取得人员、任务和材料，不能信任客户端提交的人员身份。批次包含 `batchId`；每条事件包含：

| 字段 | 含义 |
| --- | --- |
| `sessionId / seq` | 会话及从 1 递增的序号 |
| `type` | 播放、暂停、采样、翻页、隐藏等事件类型 |
| `elapsedMs` | 本会话相对单调时间；设备日期时间不决定有效时长 |
| `payload` | 视频位置或文档可见范围等类型专属字段 |

视频事件使用 `PLAY / PAUSE / WAITING / ENDED / SEEK / VIDEO_SAMPLE`；页面与应用使用 `SHOW / HIDE`；文档使用 `PAGE_ENTER / PAGE_LEAVE / DOC_SAMPLE`；退出使用 `CLOSE`。视频采样包含位置、播放状态、倍速、缓冲状态、应用和页面可见性。文档采样包含页码、渲染是否成功、可见区域起止坐标、应用和页面可见性。协议还应记录客户端版本，便于排查兼容性。

服务端保存原始载荷、接收时间、摘要及处理结果。唯一约束为 `(sessionId, seq)`：相同序号、相同内容返回原结果，不重复累计；相同序号不同内容拒绝覆盖并记录冲突。一个批次允许部分事件无效，响应逐条给出结果，不能把 HTTP 200 当成全部有效。

响应返回已收到连续序号、缺失序号范围、已确认进度、会话是否有效及过期时间。客户端优先补传最早缺失记录，未获确认的事件保留少量本地缓存。缓存仅用于重传，不代表可信离线证据。

缺序号时不跨缺口计算。尚在有效时间窗口内补齐后，可以按序处理未确认段；无法补齐或已超窗口时，记录缺口，后续从新的完整状态样本继续。旧事件迟到只保留事实，不自动回填已经封闭的缺口。服务端原始事件和进度计算结果分别保存，保留判定规则及原因，不能通过修改日志“修复”完成状态。

## 4 弱网与计时上界

客户端 10 秒无确认即暂停，提示“网络异常，进度待同步”。如果服务器仍持有有效会话、记录连续且两次有效接收间隔不超过 15 秒，可以核验这段短暂弱网记录。超过 15 秒后收到的恢复批次先留存，不能凭批内时间戳补算整个断档；使用恢复时的当前完整状态建立新基线，再接受后续在线采样。

首次接收、断档恢复、时钟倒退、切后台、缓冲和跳转均切断连续性。服务端确认时长同时受采样差值与服务器实际经过时间限制；批量上传不把请求到达瞬间当成所有样本发生时间，也不能让一次请求申报出超过实际会话经过时间的有效学习。暂停、旧会话及已知断档时间不能计入上界。

正常退出应尝试立即上报，但强杀、断电、缓存丢失时不假定尾段已完成。保留下来的已确认进度继续有效，缺失部分补学。MVP 不支持离线完成后整体补报达标。

## 5 视频核验

视频使用服务器解析并固定的时长和实际播放文件，默认全片必学、仅 1 倍速。前端不提供倍速、投屏、浮窗和后台播放入口；禁用进度手势等能力以实际组件支持为准，服务端仍需校验。可回看已经学习的内容，跳转不产生中间区域的覆盖。

只有同会话、同材料且记录连续的相邻样本才可能形成有效区间。前后必须为前台可见、正在播放、无缓冲且倍速为 1；采样间隔 `dt` 在 0 至 3 秒内，播放位置增量 `dp` 为正。中间出现隐藏、暂停、缓冲、跳转或缺序号，不能连接。

初始抖动容差取 `dp <= 1.2 × dt + 300ms`，同时任意连续 30 秒窗口内的累计推进不超过有效经过时间加 1 秒；不足 30 秒也检查现有窗口。超出则不计该段并重新建立基线，页面提示补看，不能直接认定作弊。阈值须根据真机回调表现校准，不能逐条累加容差奖励。

有效段加入已确认播放区间并求并集；有效时长增量取 `min(dt, dp)`，再受服务端时间上界约束。重复观看增加重复学习时长，不重复增加覆盖比例。暂停或结束事件携带最后位置时，按终止前的有效播放状态和相同时间规则核验尾段，再关闭计时；不要求终止事件自身仍处于播放状态，且不能仅凭 `ENDED` 完成。

默认覆盖全部必学范围。仅首尾各允许至多 1 秒的播放器精度容差，且两端合计不超过视频时长的 1%；内部缺口必须补看。保存实际覆盖和容差，不把容差写成已观察播放。达到规则时显示“已达到学习要求”，实际覆盖值保持原值。

续播定位到最早缺失位置前 2 秒，便于衔接。20 分钟视频反复观看前 10 分钟，覆盖仍为 50%；从中间跳到最后一秒，结束后仍需补看缺失区域。

## 6 PDF 逐页核验

PDF 发布时预生成固定版本的页图，保留原文件、页数、页图尺寸与校验值。管理员预览确认没有漏页、页序错误和不可读内容后发布。使用小程序内受控阅读器，按页查看、固定宽度、纵向滚动；MVP 不提供复杂缩放模式。`wx.openDocument` 的打开成功不能证明逐页阅读，其公开接口没有逐页阅读进度回调。[微信官方 API 定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)

只统计当前页：图片成功加载，应用与页面在前台，阅读区域没有被应用弹窗遮挡，才形成有效样本。可见范围按页图原始坐标记录 `[top, bottom]`；页面宽度适配阅读区，纵向超过屏幕的内容必须滚动查看。界面固定布局和工具栏需要纳入可见区域计算。

相邻有效样本属于同一页、间隔不超过 3 秒，才累计一次页面时长；同一时间片不能给多页重复计时。使用相邻样本可见范围的交集加入已确认区域并集，避免把一次快速滚动经过的全部内容自动记为已看。翻页、隐藏、图片未加载、网络断档均重建基线。

默认每页累计有效可见停留至少 30 秒，并覆盖该页 100% 的可读区域。停留阈值由管理员发布前确认，不能发布后降低以补齐旧任务。首尾按实际页图坐标裁切和像素取整，不能因为滚动组件边距制造永远无法达到的空白缺口。内容太密、适应宽度后仍不可读的 PDF 应先调整教材。

页面显示“已确认秒数、仍未显示的区域”，支持回到未完成页继续。只在首页停留很久或直接翻到末页都不能完成。页面展示与停留反映可观察行为，不能代替理解测试。

## 7 本人确认及异常处理

全部材料满足服务器规则后，显示任务名称、材料版本、完成摘要和声明：“我确认由本人完成本任务所列材料的学习，并已阅读任务要求。”学员主动确认；服务器再次核对身份、任务有效性、全部材料状态和当前摘要，变化时要求重新查看。

确认保存人员、任务、摘要、声明版本、服务器时间及请求记录，并以幂等方式将个人任务标为完成。这是点击确认留痕，不宣传为可靠电子签名。异常记录、弱网缺口或错误文件通过补学或新任务解决；管理员不能代点、强制完成或修改原始事件。

## 8 微信通知送达：MVP 必交付闭环

第一版必须实现：真实学员主动订阅后，系统向指定个人微信发送任务通知卡片，学员实际收到卡片并点击进入对应的个人任务。模板申请、真实发送、送达状态及点击进入均属于 MVP，上线验收不能只测接口调用。

任务立即发布时为每位指定学员建立首次通知；另提供管理员手动催办，发送前展示接收人员及任务。不做定时发布和自动催办。未绑定、绑定未核对通过或缺少订阅时，记录阻断原因并保留任务待办；人员完成绑定或新订阅后，可以唤醒原首次待发通知，重新检查条件后继续首次发送；这是完成原首次送达，不新增定时催办。

学员主动点击订阅按钮申请微信订阅消息，申请结果只作为发送线索，不保证可用次数。拒绝订阅不阻止学习；一次授权不保证无限发送。当前主体、类目和培训模板尚未实际核验，这些未验证项是上线门禁，不能后移为二期。系统不能保证未绑定、未授权或微信平台故障情况下送达。[订阅消息指南](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message.html)

任务发布与首次通知记录在同一数据库事务保存，后台发送器调用微信。发送失败不会丢失任务。手动催办只面向未完成人员；完成、取消及人员停用后停止尚未发出的通知。管理员界面列出待绑定、待授权、失败和结果未知人员，分别提供处理说明，不笼统显示“已通知”。

## 9 发送、送达与重发

同一微信用户串行发送；发布和手动催办各有通知记录及幂等请求号，重复点击不重复创建同一次发送。手动催办遇到同一人员任务已有待绑定、待授权、READY 或 SENDING 通知时，复用该待办，不另外制造重复通知；已有明确发送结果的记录按下述规则处理。发送前重查任务、绑定、完成状态和订阅线索，并先保存发送尝试。三个字段独立保存：

| 字段 | 状态或含义 |
| --- | --- |
| `sendStatus` | `WAITING_BINDING / WAITING_SUBSCRIPTION / READY / SENDING / ACCEPTED / FAILED / UNKNOWN / CANCELED`，描述请求发送过程 |
| `deliveryStatus` | `NOT_SENT / UNKNOWN / DELIVERED / DELIVERY_FAILED`，描述微信下发结果 |
| `openedAt` | 学员通过此通知入口实际进入个人任务的时间；没有发生则为空 |

微信接口明确成功时，保存 `sendStatus=ACCEPTED`，送达仍为 `UNKNOWN`。仅有可靠关联的微信结果回调才能置 `DELIVERED` 或 `DELIVERY_FAILED`；收到无法精确归属的回调也不能猜测成功。`errcode=0` 不等于实际送达，更不等于已读。接口明确拒绝发送时，保存发送失败及错误码，送达保持 `NOT_SENT`。

`43101` 转待授权；`43108` 检查同用户串行控制后退避；凭证过期由服务端集中刷新一次。仅明确未发出请求的连接故障、微信明确可重试的失败可以有限重试，最多 3 次，并重新检查任务及授权条件。明确失败后，管理员也可在故障已修复且授权条件满足时新建催办记录。

请求已发后超时、连接重置，或发送后结果尚未落库即崩溃，保存 `sendStatus=UNKNOWN`、`deliveryStatus=UNKNOWN`，禁止自动重发。对于接口已受理但送达未知的记录，也不能直接重复催办。确需再次提醒时，必须有学员新一轮主动订阅记录，管理员在看到原未知状态和可能重复送达的提示后明确确认，再建立新的通知和发送尝试。保留原记录及两次通知关联，不把未知覆盖成失败。

微信凭据仅在服务端受控配置中使用，不返回小程序、不写入普通日志。错误码和模板参数按官方接口核对。[发送订阅消息接口](https://developers.weixin.qq.com/miniprogram/dev/server/API/mp-message-management/subscribe-message/api_sendmessage)

## 10 回调与点击进入

微信回调按官方签名和加密协议验证，检查接收 AppID，验签成功后持久化并去重；重复回调不重复更新状态。XML 禁用外部实体并限制大小，密钥不进入前端。无法验签的请求不能改变通知记录。[微信消息推送协议](https://developers.weixin.qq.com/miniprogram/dev/framework/server-ability/message-push.html)

发送结果只有取得可靠 `msgid` 等关联键时才能归属具体尝试。关联成功的回调确认成功或失败后，更新对应 `deliveryStatus` 并保留回调依据；先到的回调可独立保存，后续取得可靠键再关联。没有可靠键时保存未关联回调，送达保持 `UNKNOWN`，不能按“最近一条同用户消息”归属。冲突回调保留原文并标记异常，不能静默覆盖确定结果。

卡片链接包含不透明个人任务及通知 ID，不含姓名、手机号或登录凭据。学员点击后仍需登录并检查本人任务权限，通过后写入 `openedAt`；从普通待办进入仅记录任务访问，不伪造通知入口打开。已打开与送达结果独立保留，不把访问记录当成微信回执。通知被转发后其他人不能越权学习。

后台并列展示“发送状态、送达结果、通知入口打开时间、任务完成状态”。没有可靠回执但本人已经进入时，可以显示“送达结果未知，学员已从该通知入口进入”，不使用“微信已读”。

## 11 MVP 验收门禁

学习功能必须在 iOS、Android 真机验证播放回调、锁屏/来电/切后台、全屏、页面滚动和弱网。至少通过：重复观看不重复覆盖；快进末尾不能完成；10 秒无确认停止计时；超过 15 秒断档不补算；旧会话不累计；缺号重传不重复计时；PDF 翻到末页不完成；本人确认前服务端复检。

微信送达必须使用永森油服实际 AppID、获批模板及真实学员微信：学员主动授权，管理员向指定人员发任务，手机实际收到正确卡片，点击进入对应个人任务。保存本次通知、授权、发送、回调和进入记录，核对三项状态。模拟回调、接口返回成功或仅后台显示成功均不能替代这项验收。
