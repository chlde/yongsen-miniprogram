# 管理后台首次使用教程

更新：2026年10月17日。

管理员首次登录后，后台自动展示六步操作指引，说明先点哪个入口、进入页面后再点哪个按钮。顶部“使用教程”可随时重新打开；“上一步”“下一步”切换步骤，“稍后再看”退出，“完成教程”结束。

| 步骤 | 高亮入口 | 说明内容 |
| --- | --- | --- |
| 欢迎使用 | 培训工作台 | 介绍从准备人员、资料到发布和跟进培训的流程 |
| 添加员工并开通学习 | 员工管理 | 添加员工、生成个人邀请码、员工提交申请、管理员核对通过 |
| 准备培训资源 | 培训资源 | 上传MP4/PDF、等待处理、预览并确认可用于培训 |
| 配置微信提醒 | 通知设置 | 填写模板、保存、检查；本地模拟与实际收件的区别 |
| 发布培训任务 | 培训任务 | 填写名称与要求、选择材料及人员、核对后发布 |
| 跟进学习结果 | 培训任务 | 查看员工进度、通知状态、学习详情，导出或打印记录 |

教程高亮现有导航入口，并用具体按钮名称说明后续操作；不自动切换业务页面或提交任何业务表单。因此重新查看教程不会卸载当前表单，不会创建员工、上传资料、发布任务或发送提醒。教程适用于没有员工、材料和任务的首次使用场景。

## 服务端状态

教程版本为 `admin-basics-v1`。`GET /api/v1/admin/onboarding` 读取当前管理员状态；`PUT` 保存跳过或完成。未开始、已跳过、已完成分别为 `NOT_STARTED`、`DISMISSED`、`COMPLETED`。

状态按管理员账号和教程版本保存到服务端，刷新、重新登录或换浏览器后继续生效。跳过后不再自动出现，但可手动重播。已完成状态不会因重播中途退出而降级。教程状态不代表任何员工已完成培训。

存储复用现有 `app_config` 的独立命名空间，没有新增表或数据库迁移，不影响通知模板配置。客户端不能指定其他账号；未登录及学员无法读写。重复提交保持幂等，服务端保存时间用于核对状态。

读取失败不阻止后台业务操作；保存失败保留教程并提示未保存，可重试或仅关闭本次。仅关闭不会假报持久化成功。弹窗支持键盘焦点约束和 Escape 退出，并适配手机宽度。

## 验证入口

执行 `npm run verify`，使用独立数据库验证教程和原有培训流程。`tests/e2e/00-onboarding.spec.ts` 必须在新数据库上先运行，以验证实际首次状态；现有业务测试通过显式跳过教程继续操作。

验收包含：首次自动出现、跳过后刷新不弹、完成后新浏览器不弹、6步入口高亮、全程无业务写入、手机布局、重播保留表单、键盘退出、读写异常恢复、权限及参数边界。备份恢复检查同时核对教程完成状态。
