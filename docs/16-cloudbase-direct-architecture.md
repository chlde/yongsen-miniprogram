# 永森油服 CloudBase 直连架构

更新：2026-10-21。本文对应 2.0 实现。旧 Java、Web 管理端、HTTP 网关和 MySQL 代码已退出当前系统；采用新集合和新任务，不迁移旧业务数据，不提供旧架构回退。

## 系统结构

![云开发架构](diagrams/16-cloudbase-target.svg)

图中蓝色为应用及执行组件，绿色为数据存储，白色为外部平台；实线箭头表示请求方向。CSV 在小程序本地生成。

小程序通过腾讯云 SDK 查询、监听数据并提交云函数命令。云函数是腾讯云托管的可信执行边界，负责客户端不能自行裁定的权限、进度和完成状态，不需要部署和维护独立 API 服务。

| 单元 | 职责 |
| --- | --- |
| 原生小程序 `pages/` | 微信身份、员工绑定、任务列表、视频与 PDF 学习、本人确认、记录 |
| 管理分包 `admin/` | 员工、教材、任务、成员权限、订阅模板、进展监控、CSV 导出 |
| `ys-training` | 微信上下文校验、角色与员工绑定、业务命令、学习事件事务、完成记录、媒体授权 |
| `ys-jobs` | 分批发布、任务提醒、微信发送结果与未知结果处理，每分钟调度 |
| `ys-materials` | 校验文件大小与格式、H.264 元数据、PDF 页图、内容哈希与教材固定版本 |
| CloudBase 文档库 | 业务数据与事务、权限规则、实时监听 |
| 私有云存储 | 临时上传对象、不可由客户端修改的教材文件与页图 |

## 身份与角色

身份来自 `wx-server-sdk.getWXContext()`，同时校验 OpenID 与当前 AppID。客户端上传的账号标识、角色和进度不作为授权依据。

业务角色映射为：微信平台管理员 → `ADMIN`；所有项目成员 → `ADMIN`；仅体验成员及其他用户 → `USER`。项目成员的运营、开发或分析勾选项不进一步限制业务管理权限。

成员来源存放在 `ys_roles.sources`，可同时包含 `PLATFORM_ADMIN` 和 `PROJECT_MEMBER`。撤销一个来源后仍有另一个来源时继续保留 `ADMIN`。每次管理写操作重新读取角色，避免仅靠前端隐藏按钮。

平台成员页面中的微信昵称、掩码微信号不能转换为小程序 OpenID。运行时也没有可直接同步该页面完整成员名单的已验证能力。因此采用显式核验：成员登录生成短期核验码，已有管理员对照公众平台名单设置来源，记录核验人、时间与说明。成员新增和移除后需要更新这份映射。首位管理员仅通过可信部署身份初始化，禁止公开自助认领管理员。

普通员工绑定流程：管理员创建工号 → 签发一次性邀请码 → 员工通过真实微信身份申请 → 管理员核对通过 → 绑定生效。邀请码只保存哈希，签发新码会撤销旧码。

## 数据与权限

| 集合 | 数据 |
| --- | --- |
| `ys_roles`、`ys_role_requests` | 微信身份角色、平台成员来源、短期核验码 |
| `ys_people`、`ys_invites`、`ys_bindings` | 员工、邀请码、待核对绑定 |
| `ys_materials` | 教材处理状态、内容哈希、视频信息或 PDF 页面信息 |
| `ys_tasks` | 冻结的任务、教材规则及目标人员 |
| `ys_assignments` | 每位员工的任务副本、逐教材进度与确认状态 |
| `ys_sessions`、`ys_session_locks`、`ys_batches` | 学习会话互斥、顺序事件、重传去重与审计数据 |
| `ys_completions` | 本人确认时的进度摘要与完成记录 |
| `ys_jobs` | 分批执行游标、租约、失败原因与重试状态 |
| `ys_subscriptions`、`ys_notifications`、`ys_settings` | 客户端授权反馈、发送尝试、模板配置 |
| `ys_audit` | 管理操作记录 |

`cloud/security-rules.cjs` 是部署权限的唯一源。所有集合禁止客户端直接写入；普通用户仅可读取自己的身份和可见任务/记录；管理员可查询管理数据。邀请码哈希、会话内部状态、核验码申请等仅能经云函数访问。后台作业与教材函数禁止客户端调用。

云存储保持客户端默认拒绝读写。上传前先核验管理员身份，再签发随机临时对象的上传凭据；客户端直接向腾讯云存储上传。处理函数校验文件、计算 SHA-256 并写入固定教材路径。已发布任务引用不可变文件；上传凭据不能改写正式教材。媒体临时地址通过员工身份和任务归属校验后签发，默认 10 分钟有效。

复合索引在 `cloud/indexes.cjs`，覆盖个人可见任务、任务进展、作业状态、通知状态和订阅授权查找。

## 任务与学习流程

任务创建时读取 READY 教材并冻结元数据、规则和目标人员。发布以稳定任务 ID、每人唯一分配 ID 和事务游标执行，每批 15 人；全部分配成功后任务变为 ACTIVE，再分批设置个人任务可见。未绑定人员导致明确失败，可处理原因后重试，不产生重复分配。

普通用户学习状态：`NOT_STARTED → IN_PROGRESS → READY_TO_CONFIRM → COMPLETED`。管理员无法直接代填完成。会话开始、事件写入、媒体访问和完成确认都检查当前任务是否仍有效；任务取消立即阻止继续学习。

每个微信账号只有一个有效会话。切换设备需要显式接管，旧会话失效；会话租约为 30 秒。客户端每秒采样、每 5 秒提交、10 秒无确认时暂停。云端对批次、序号和内容哈希去重，缺失序号等待后关闭缺口，过久离线不会补算时长。

视频必须保持可见、正常播放、无缓冲、1 倍速，并满足客户端时间间隔与服务端时间预算。有效区间取并集，内部缺口不可直接通过；仅容忍总计不超过视频时长 1%、单侧不超过 1 秒的首尾误差。

PDF 渲染为固定页图，统计原图坐标下实际可见区间及每页有效停留。每页至少 30 秒且覆盖整页，全部页面达标才可确认。页面滚动或切换时重新测量可见区域。

确认请求必须包含本人勾选、确认文案版本和最新进度摘要。云端原子写入不可由客户端改写的完成记录和完成状态。在线学习记录不替代知识理解、线下实操或岗位资格考核。

## 通知与监控

小程序在用户点击时调用 `wx.requestSubscribeMessage`，请求前生成带随机 nonce 的短期记录。客户端报告“同意”只代表授权反馈，实际可发送次数仍由微信裁定。

发布或管理员提醒生成待发送通知。只有任务 ACTIVE、员工绑定有效且有可用授权反馈时才尝试发送。发送前领取租约并记录 SENDING；微信受理记 ACCEPTED、明确拒绝记 REJECTED、网络超时或发送后崩溃记 UNKNOWN。UNKNOWN 不自动重发，避免重复消耗授权和重复通知。已完成人员不再提醒，同一任务提醒间隔至少 1 小时。

“微信已受理”不是送达回执。当前实现不声称能够确认手机已阅读；实际手机收到卡片、点击进入正确任务需独立验收。小程序未取得订阅授权时，任务仍可从任务列表进入。

管理员通过云数据库监听任务进展；断开连接时显示刷新提示。发布/教材失败原因保存在作业记录，可从工作台重试。CSV 导出包含员工、任务、状态和确认时间，并防止表格公式注入。

## 部署

环境固定为 `yongsen-prod-d4ghriorcc1483d38`（上海）。运行 `npm run build` 后，`cloud/dist/` 中包含三个独立函数包。运行时为 Node.js 20.19；培训与作业函数 512 MB，教材函数 2048 MB。教材包显式包含 Linux x64 渲染依赖。

`npm run deploy:cloud` 创建/检查集合与索引、应用数据库与存储规则、部署函数、设置调用权限并创建每分钟触发器。配置更新不携带重复安装依赖参数，代码以 ZIP 上传；部署后通过真实函数调用回读构建哈希，教材函数额外加载原生渲染模块。不能以 Active 状态替代版本核验。

函数调用规则是环境级映射，具体函数名优先于 `*`。部署程序保留环境中其他函数的规则，为 `ys-training` 设置非匿名登录要求、为 `ys-jobs` 和 `ys-materials` 禁止客户端调用，再回读核验。业务角色和 AppID 仍由函数内部检查。

腾讯云部署与微信 OpenAPI 授权是不同环节。首次启用订阅消息时，需使用已登录且具备 AppID 权限的微信官方 CLI 注册函数包中的 `config.json`：

```sh
/Applications/wechatwebdevtools.app/Contents/MacOS/cli cloud functions deploy \
  --env yongsen-prod-d4ghriorcc1483d38 \
  --paths "$PWD/cloud/dist/ys-training" "$PWD/cloud/dist/ys-jobs" \
  --appid wx505c1dc50f1f7099 --remote-npm-install --report
```

调用后须重新核对运行包哈希和调用权限。首位管理员需要先在真实小程序登录，由可信部署身份核验其平台成员资格，再给对应的 `ys_roles` 文档设置 `ADMIN` 和有效成员来源，不能根据截图昵称猜测 OpenID。本次已完成当前开发成员初始化；其他成员使用小程序中的核验码流程加入。

当前订阅模板为“新任务发布通知”，映射为 `thing1 → title`、`time20 → dueAt`。`WECHAT_RELEASE_STATE` 控制消息跳转到 `developer`、`trial` 或 `formal`，必须与可访问的小程序版本一致。本次为开发版验收配置了 `developer`；正式版本发布后再切换为 `formal`。部署脚本不会读取 `.env`，需在终端环境显式导出相关配置。

生产小程序通过官方 CLI 上传构建目录。上传成功不等于提交审核或正式发布。真实部署结果、原生测试与剩余验收项见 [部署与验收记录](17-cloudbase-v2-acceptance.md)。

规则语法依据：[CloudBase 数据库安全规则](https://docs.cloudbase.net/database/security-rules)、[跨文档函数限制](https://docs.cloudbase.net/rule/reference/function)、[云存储安全规则](https://docs.cloudbase.net/storage/security-rules)、[云函数安全规则](https://docs.cloudbase.net/cloud-function/security-rules)、[腾讯云资源权限接口](https://cloud.tencent.com/document/product/876/132255)。
